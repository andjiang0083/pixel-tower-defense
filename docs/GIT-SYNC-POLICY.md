# GIT / 远端同步政策

> 从 v0.5.4 起生效。这不是"常识提醒"，是**门禁**：`python3 tools/gh_preflight.py --pre`（开工）、
> `--post`（收工）。红灯就停下对账，别"先改再拉"。

## 为什么写这个（真实事故）

2026-10-17 这一轮：会话从头到尾**一次 `git fetch` 都没做**，也**没跑商店巡检**。结果

1. 用**未推送的提交**构建并发布了一个商店版本 —— 镜像在商店、提交只在本地 ⇒ **别人无法复现**，
   事后也没法用「商店那份 == 哪个提交」来对账；
2. 仓库台账（`publish.yaml` 的 `readback:`）还停在 `v0.4.3 PENDING`，而**线上 10-13 就
   `PUBLISHED v0.4.4`** —— 台账落后线上整整一个版本。这个检查工具早就有了
   （`~/esp32/tools/store-audit.py`，零登录），是**习惯**没到位，不是工具缺。

教训一句话：**规范治不住"事件"，只有门禁治得住。**

## 三个真源，关系固定

| 东西 | 真源 | 说明 |
| --- | --- | --- |
| 代码 | GitHub `andjiang0083/pixel-tower-defense` 的 `main` | 本地任何树都只是**工作副本** |
| 商店状态（版本 / 审核 / 已发布） | M5Burner 线上接口（公开接口零登录可查） | 台账必须**回读**它对账，不许凭记忆写 |
| 发行件 | `releases/<name>-vX.Y.Z-tab5-merged.bin` + `.sha256` | 校验值入库；bin 走 Release 附件 |

派生方向（**只允许图中的方向**）：

```
GitHub main ──clone / pull──▶ 工作副本（WorkBuddy/…）──push──▶ GitHub main
                                     │
                                     └── 只带"发行件 + 台账" ──▶ ~/esp32/tab5-tower-defense
                                                                 （流水线目录）
```

- `~/esp32/tab5-tower-defense` 是**流水线目录**（`release.py` / `store-copy.json` / 封面在此），
  **不是第二份开发树**：禁止在那里改源码，禁止把源码改动从那儿反向带回主树。
- 台账（`publish.yaml` + 商店文案）只许有**一个格式、一处权威位置**；发现第二份就在同一次提交里合并掉
  —— 双副本必漂移。

## 开工：三步（`gh_preflight.py --pre`）

1. **`git fetch`** → 落后必须为 0。落后或分叉就**停下对账**，禁止"先改再拉"。
2. **台账对账**：仓库台账 vs 线上商店。判据是**版本先后**：
   - 线上版本 == 台账 readback 的 vid → 一致 ✅
   - 线上版本 < 台账记录的（在审）版本 → **在途**，正常 ✅
   - 线上版本 > 台账记录的版本 → **漂移**，红灯 ✗（10-13 那次就是这种）
3. 确认工作在**最新远端提交**之上（把 `git log --oneline -1 upstream/main` 记进会话/文档）。

## 收工：四步（`gh_preflight.py --post`）

1. 提交：一个动作一个提交，写清"为什么"（不是"改了什么"）。
2. **push**，并校验哈希相等：`git rev-parse HEAD == git rev-parse upstream/main`。
   —— 哈希相等才叫"同步"，`ahead N` 不算。
3. **发行件必须由已推送的提交构建**（`--post` 里"有未推送提交 = ✗"拦的就是这条）。
   顺序：commit → push → 从该提交构建 merged → 上传商店 → 回读 → 写 `readback:` → commit。
4. 回读商店（登录态看 PENDING / 公开接口看 PUBLISHED），把 `readback: <日期> <状态> vid=<vid>`
   写进 `publish.yaml`（两棵树都写，**以公开仓那份为权威**），并 `git commit`。

## 边界（谁说了算）

- **公开动作**（push、建 Release、上架商店）要用户明确发话。
- **删除 / 覆盖**（删仓库分支、删商店版本、覆盖远端历史）必须先拍板，且只许做被拍到的那一件。
- 一次会话内远端若动了：以远端为准 rebase；`publish.yaml` 冲突取**远端版**
  （rebase 语义下 `--ours` = 远端基，方向与 merge 相反，别搞反）。
- 会话结束前把"没做完的事"写进 commit 或 `docs/`，别只留在聊天里。
